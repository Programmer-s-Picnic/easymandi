## How to restore b1 if authorized later

1. Pause ordering, delivery status changes, and payment processing.
2. **First preserve the state being replaced** as a separate timestamped safety backup; any post-b1 orders/payments must be handled before restoring older data.
3. Restore the exact commit SHA above in each repository to appropriate release branches, carefully preserving the `b1` branches. Re-run the applicable build/deployment workflows only after verification.
4. Restore the SQL database backup and the JSON/media archive together on the GoDaddy host, retaining all internal database relationships. Use the stored `manifest.json` SHA-256 checksums before restoration.
5. Verify login, catalogs, the unique public order references, historical and pending orders, payments, partner assignments, status events, handoff QR scanning, notifications, and the three public APK download URLs.

Restoring the b1 database **is destructive to later production changes**; obtain approval before performing it. This checkpoint creation did **not** roll back or alter the live system.
